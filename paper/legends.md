# Figure legends

**Fig. 1 | NSCLC-Agent: a model-led consultation runtime on a deterministic clinical kernel.**
The clinician writes in Chinese or English, either in a static web app (the Python kernel runs in the browser via WebAssembly) or at a command line; both reach the same session through one JSON interface. In agent mode the lead agent is a language model from any supported provider (blue). It reasons in a loop, calling tools, reading their results and choosing the next step, until it submits a consult. Along the way it plans the work-up as a live checklist, keeps structured case notes, runs read-only tool calls concurrently and delegates focused questions to seven specialist sub-agents (blue). Each specialist has its own context and a read-only tool allow-list (Extended Data Fig. 1). The session holds the plan, the case notes, memory that the clinician confirms, checkpoints for rewinding and compaction near the context limit. Eight deterministic hooks (grey) run at fixed points: when a message arrives (emergency screen, case-note seeding), after each tool call (evidence ledger) and when the consult is submitted (rule engine, stage consistency, citation provenance, dose provenance, emergency first). Their findings are advisory: they return to the model, which must revise its consult or justify an override. No hook blocks or rewrites the output. Stage group, indications, rule findings and doses come from the deterministic kernel through tools and hooks, never from the model. The same kernel acts as a hard control plane in governed mode (Extended Data Fig. 3). Dashed outlines mark optional or external components. Counts are read from the code base when the figure is built. KB, knowledge base; MCP, Model Context Protocol; REPL, read–eval–print loop.

**Fig. 2 | Stage is computed by a deterministic engine and is never generated by the model.**
**a**, Stage group assigned by the AJCC/UICC 9th-edition staging engine for every T and N category at M0. Under-specified descriptors (bare T1, T2 and N2; TX and NX) are shown below and to the right of the rules. A bare family is staged only when every subcategory gives the same stage group (for example, T1 N1 is IIA for T1a, T1b and T1c); otherwise it is refused (grey) and the engine names the test that resolves the ambiguity rather than guessing. TX N0 M0 is staged as occult carcinoma. **b**, Stage for each M category (T2a N0). Bare M1c is staged IVB because M1c1 and M1c2 agree; M1 and MX are refused. **c**, Accuracy of the governed pipeline on the gold-standard set (n = 70 cases: 42 end-to-end pipeline cases and 28 audit probes; denominators are the cases that test each property). Points show proportions; lines show exact (Clopper–Pearson) 95% confidence intervals. Vermillion, a lower value is better.

**Fig. 3 | Advisory hooks surface defects injected into agent consults.**
**a**, Clean consults were built from the 35 plans that the governed pipeline released for the gold-standard pipeline cases. One labelled defect was then injected into each consult, and the agent-mode stop hooks were run. Rows show each defect class and the proportion of consults in which the expected finding was raised. The bottom row shows consults with no defect that raised any finding (2/35; both were warnings that the governed pipeline itself attaches: trial edition migration and progression on the same drug). Two defect classes apply to subsets only: a regimen outside its declared population (stage 0–III cases, n = 9) and immunotherapy despite an actionable driver (stage IV with an actionable driver, n = 18). **b**, Every finding raised, as a proportion of consults; rows as in **a**. Co-occurring findings come from independent checks; for example, a dose figure in model output triggers both the dose-provenance hook and the rule engine's dose scan. Points show proportions; lines show exact (Clopper–Pearson) 95% confidence intervals. Defects were constructed by the authors; the experiment measures how much of the defect space the hooks cover, not how often language models make these errors.

**Fig. 4 | Runtime properties: concurrent specialists and a bounded context.**
**a**, Wall-clock time of a multidisciplinary consult as a function of the number of specialist sub-agents, run one after another (grey) or concurrently (blue). Model calls were simulated with a fixed latency of 250 ms per call. Tools were real. Each specialist made two model calls and the lead agent made two. Points show medians of n = 5 repeats; bars show the range. Concurrency is capped at six worker threads, which accounts for the step at seven specialists. **b**, Estimated prompt size over a 24-turn consult (offline mock model) without compaction (grey) and with compaction (blue; context window 16,000 tokens; compaction triggered at 60%, dashed line). Open circles mark the turns at which compaction occurred. Token counts are provider-neutral estimates: one token per Chinese character and one per four other characters.

**Fig. 5 | A worked consult: the hooks catch an 8th-edition stage and immunotherapy consolidation in EGFR-mutant disease, and the model revises.**
**a**, The case: unresectable cT2bN2bM0 adenocarcinoma with EGFR L858R (example iiib_egfr in the web app). The AJCC/UICC 9th-edition staging engine reads stage IIIB; under the 8th edition the same descriptors were IIIA. **b**, Timeline of the consult in agent mode with English output. The lead agent planned, staged and read the driver report in one concurrent step. It then delegated to the radiologist and the medical oncologist, who ran concurrently, and submitted a draft. After the hooks' findings it called the indication check and trial search, and resubmitted. Model calls were simulated with a fixed latency of 0.6 s per call. Tools, sub-agents and hooks were the real runtime (9 model calls, 4.2 s). **c**, The review loop. The model's decisions were scripted by the authors to reproduce a common error: the draft gave the 8th-edition stage and durvalumab consolidation (PACIFIC). The stop hooks raised three findings, shown verbatim. The revision accepted all three and gave stage IIIB with osimertinib consolidation (LAURA). It raised no findings on resubmission and proposed the same regimens as the governed pipeline's reference opinion. **d**, Every regimen in the library (n = 40) checked against the case with its declared, machine-executable indication predicate. Columns are regimens grouped by setting; rows are predicate conditions; the top row marks eligible regimens (2 of 40). Numbers on the right count the regimens that fail each condition. Outlines mark regimens proposed in the revision (solid) and in the draft only (dashed). CM, CheckMate; CRT, chemoradiotherapy; Dato-DXd, datopotamab deruxtecan; KN, KEYNOTE; LCT, local consolidative therapy; SBRT, stereotactic body radiotherapy; SCLC, small-cell transformation; T-DXd, trastuzumab deruxtecan.

**Extended Data Fig. 1 | Tool access of the lead agent and the specialist sub-agents.**
Each column is a clinical tool and each row an agent. Grey, the lead agent, which can call every clinical tool and is the only agent that writes the case notes, updates the plan, delegates and submits the consult. Blue, the read-only allow-list of each built-in specialist sub-agent. Specialists cannot delegate further or submit the consult. Custom specialists are declared in the same way: a name, a role, a prompt and a tool list.

**Extended Data Fig. 2 | The knowledge substrate of the clinical kernel.**
**a**, Recommendations in the built-in guideline knowledge base by source guideline. The 2,960 recommendations are machine-extracted and clinically unreviewed, are grouped in 147 cross-guideline clusters, and serve as non-releasable context only. **b**, Size of the deterministic kernel and of its evaluation set. **c**, Recommendations by guideline and topic; the nine most frequent topics are shown and the rest are pooled as other. **d**, Registry trials by treatment setting and by the 9th-edition stage groups they enrolled; a trial is counted once in every stage group it covers. In **c** and **d**, shading scales with the square root of the count and empty cells are zero. LA, locally advanced; TCM-WM, integrated traditional Chinese and Western medicine.

**Extended Data Fig. 3 | Release states of the governed pipeline.**
In governed mode the kernel is a hard control plane. A case passes through fixed steps (centre) and leaves at the first one that stops it (right). The critic can send the treatment plan back for repair a bounded number of times; a block finding that survives the loop stops release. A dose-bearing draft is produced only for an oncologist who opted in and only when every gate passes, and it still awaits sign-off by the tumour board, which is recorded outside the system. Any exception, and any divergence when a recorded run is replayed, fails closed, and a resumed run never reopens a safety decision. Counts are the release states of the 42 end-to-end gold-standard cases. In agent mode the same checks run as tools and advisory hooks (Fig. 1).
